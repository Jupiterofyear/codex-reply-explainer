# 数据如何处理

插件读取用户选定的本地聊天记录，以及生成分支所需的 Codex 配置、模型信息和已有登录状态。

为创建临时分支，记录会临时复制到所选解释数据目录中的独立 Codex 存储目录。登录文件 `auth.json` 也会临时复制，启动或单次生成后删除。配置及后台日志在小窗关闭后随后台目录删除；窗口大小和位置单独保留。

完整有效上下文和解释请求会发送给当前配置的模型服务。使用 ChatGPT 登录时由 Codex 使用该账号已有的服务；使用其他提供商时遵循该配置。插件没有自己的服务器，不收集遥测，不把对话上传到 GitHub。

小窗打开时，当前解释以本地临时 JSON 保存以供显示。切换或关闭小窗后删除；它不会作为用户消息或助手消息加入主聊天。模型被要求只解释、不调用工具。需要交互确认的后台请求会被拒绝。

尚未发布的“提问”功能会把问题和回答临时保存在同一个显示目录，并把后续问题追加到内存中的独立临时分支；不会创建长期侧栏聊天或向主聊天追加消息。重置、切换聊天、关闭窗口会释放该分支；切换和关闭也会删除问答显示文件。主聊天继续产生新回复时，已有问答分支保留。重新开始后的第一问才读取最新完整上下文。后台异常退出后重启会清除遗留问答，用户需要重新提问。

问答分支禁用配置中的 MCP 服务、插件和连接器，使用只读沙箱并拒绝交互执行请求。模型另外被要求只根据上下文回答，不调用工具；这项提示词本身不构成操作系统隔离。问题及继承的上下文同样会发送给所配置的模型服务。

“解释当前聊天”按钮激活 Codex 窗口，使用复制应用内链接的快捷键读取聊天标识。在用户未再次修改剪贴板时，恢复原有剪贴板内容。

清理发生于正常生成结束、切换或关闭。断电、强制结束进程等情况可能留下临时文件；关闭解释进程后，可删除自己指定的数据目录中的 `backend`、`renderer`、`runs` 和 `floating`，保留 `window-layout.json` 即保留窗口位置。不要删除主 Codex 存储目录。

为排查后台退出，数据目录还会保留 `worker-error.log` 和 `worker-exit.json`，记录最近一次后台启动的错误输出及退出状态。错误输出可能包含本地文件路径；下次启动覆盖错误日志，退出时更新退出记录。分享前检查这些文件，也可以在关闭解释后台后自行删除。它们不会上传到 GitHub。

报告问题时只提供错误信息、程序版本和必要的复现步骤。不要提交聊天记录、登录文件、私人配置或解释数据目录。
从 beta.3 开始，Codex 会连接本项目的 GitHub 仓库以检查和下载插件更新。个人安装设置保存在 Codex 存储目录的 plugins/reply-explainer-settings.json；其中包含解释数据目录和程序路径，更新时保留，不随插件上传。
