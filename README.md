# Codex Reply Explainer · Codex 回复解释

[English](README.en.md) | 简体中文

**本插件使用 Codex 官方的 `thread/fork` 接口创建临时分支，继承主聊天上下文，尽量复用已有输入缓存。** 在独立小窗中解释 Codex 的回复，也能结合这段聊天继续提问；解释和问答都不写回主聊天。

测试版 **0.5.0-beta.3**，支持 Windows x64 上的本地 Codex / 本地 ChatGPT Work 聊天。普通 Chat、Work Cloud 和远程主机聊天暂不支持。此项目由社区开发，与 OpenAI 无隶属关系。

当前功能统一维护在 [`main` 主分支](https://github.com/Jupiterofyear/codex-reply-explainer/tree/main)，安装和自动更新也跟随这个分支，无需另外切换提问功能分支。

## 解释与提问

小窗包含“解释”和“提问”页签。小窗通过 Windows 可访问性接口读取侧栏选中的聊天，约每秒同步一次，无需先在主窗口发消息，不自动生成解释。解释页底部的“解释当前对话”按钮才会启动生成；提问可点击发送或按 Enter，Shift+Enter 换行。主窗口切换聊天时自动选择对应的小窗标签；手动点回旧标签后停留在那里，直到主窗口再次切换。解释和提问针对当前标签中的聊天。标签位于“解释 / 提问”下方，可横向滚动，分别保留正文、问答、草稿和阅读位置。

自动同步需要主窗口侧栏显示当前选中的聊天，且只保留一个 Codex 主窗口。通过聊天名称与本地记录唯一匹配；有同名聊天时会明确提示改名，不随意选择。识别不抢焦点、不使用剪贴板。当前讨论名称显示在页面上，切换聊天保留正在输入的草稿。

首次提问从所选主聊天最新完整回复的有效上下文创建临时分支，沿用模型和思考强度。主聊天和提问提示词都未变化时，追问在同一分支继续；主聊天有新完整回复后，下次发送才创建新分支，保留小窗里可见的问答，并将旧问答作为标明来源版本的历史材料带入一次。旧讨论不代表当前进度，事实与进度以最新主聊天的证据为准。默认回答风格通过分支的固定指令设为简洁、无防御性、有信息量，不在每条用户问题中重复。点“重新开始”会清空问答并释放旧分支；下一次发送只读取主聊天最新完整回复。同一聊天再次绑定或切回标签会保留问答和分支，切到别的聊天时已有生成继续完成；关闭小窗时统一清理所有标签及临时分支。后台意外退出后，重新启动会丢弃旧问答，不自动重发问题。

解释与问答各有独立后台和临时分支，可以同时生成，无需相互等待。生成时发送键变为停止键，点击后保留已收到的内容并可继续追问。思考提示按后台真实事件显示：首次思考在回答上方，输出后再次思考时在对应段落下方显示，文字带周期光效并逐秒计时；已结束的阶段保留思考用时，完成或停止后保留总用时。切换聊天后计时延续。系统开启减弱动画时取消光效。重新开始只取消正在生成的问答，不影响解释。输入框和正文自动读取 Codex 的界面字号，代码读取代码字号；修改设置后小窗自动更新。问答禁用连接器和 MCP 插件，使用只读沙箱并拒绝交互执行请求；提示词要求根据已有上下文回答、不调用工具。工具配置与原聊天可能不同，因此缓存命中率需要单独测量；上文和下文的历史解释测试数据不代表提问性能。

窗口可缩窄：日常小窗最小宽度为 240，设置窗口为 320（均为 Windows 逻辑尺寸；150% 缩放时约为 360 和 480 像素）。窄窗口中标题省略、正文留白缩小；设置页显示较短页签，底部按钮分为两排，放宽后恢复原布局。字号仍跟随 Codex，不随窗口缩小。

本地开发与验证方法见 [VALIDATION.md](VALIDATION.md)。

## 自定义提示词

点击小窗顶部的齿轮按钮，分别编辑“解释提示词”和“提问提示词”，点击“保存设置”后应用于所有聊天；也可恢复当前项的默认文字。设置保存在解释数据目录中的 `prompt-settings.json`，关闭小窗或更新插件后仍保留。取消会放弃尚未保存的修改。每项最多 32000 字，留空表示不添加这项回答要求。

“工作原理”页用于阅读说明，底部的恢复默认、取消和保存按钮会全部隐藏并禁用，正文向下扩展。切回任一提示词编辑页，按钮恢复显示和使用；未保存的编辑会保留。关闭设置窗口可点击右上角的关闭按钮。

提示词说明**怎样回答**，继承的聊天上下文提供**讨论依据**。解释时，程序把基本解释请求与自定义要求一起作为本轮请求发送；修改后即使主回复没变，也能重新解释。提问时，自定义要求作为分支的固定应用指令传入，优先级高于普通用户消息。主聊天有新完整回复，或提问提示词改变后，下一问会建立新分支，并将可见小窗问答作为历史材料带入；程序另有固定说明，区分过去讨论与当前进度。只修改解释提示词不会重建提问分支。已经开始的生成和已有回答不受保存操作影响。

写法示例：“先给结论，再给两三条关键依据；涉及计算时保留必要推导。”要求应清楚且相互一致，反复重复或无限加长不会保证更好的结果。留空时解释仍发送基本解释请求，提问仍保留历史来源说明；修改文字不会改变工具权限或模型与环境中优先级更高的要求。设置页“工作原理”内有完整说明，也可参考 [OpenAI 提示词文档](https://developers.openai.com/api/docs/guides/prompt-engineering)。

## 它怎样工作

- 选择一段聊天，读取截至最新完整回复的本地记录。
- 从这些记录创建临时分支，沿用原模型和思考强度，尽量复用输入缓存。压缩过的聊天沿用压缩后仍有效的上下文。
- 插件会自动启动并复用后台；仅在点击“解释当前对话”或发送问题后生成内容。
- 解释和问答只显示在小窗，不写回主聊天。切换聊天时保留各标签的内容；关闭小窗时清理全部临时内容和后台，保留窗口大小与位置。生成结束后删除上下文与登录信息的临时副本。
- 支持 Markdown 和常见数学公式。
- **记住上次关闭时的窗口大小和屏幕位置，下次打开自动恢复。**

## 与官方自动填充共同使用的临时分支机制

fork 就是从已有对话创建一个独立分支，带着对话上下文生成新内容。Codex 官方自动填充也采用临时分支生成建议。本插件通过官方 `thread/fork` 接口和 `ephemeral: true` 创建解释分支；临时分支只在内存中运行，不加入长期保存的聊天列表。接口说明见[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

解释分支继承截至最新完整回复的有效上下文，因此能结合之前的问题、限制，以及用户在对话中表达的关注点和偏好来解释。对已经压缩的历史，沿用压缩后仍有效的内容。原模型和思考强度也会沿用。

两者创建分支的位置有所区别：核对过的官方自动填充从桌面端已加载的聊天状态创建预测分支；本插件在独立后台中，从已保存的本地记录创建临时分支。后台的启动、复用和关闭均由插件自动处理，主聊天继续独立运行。具体调用见 [src/backend.mjs](src/backend.mjs)。

## 缓存命中实测

保留已有上下文和模型配置，可以让服务端复用已处理的相同输入。**0.5.0-beta.2 在新回复结束后的自动解释实测，输入缓存命中率为 93.5%。** 下表同时保留前一版本的两次测量。

| 请求 | 全部输入 token | 命中缓存的输入 token | 缓存命中率 |
|---|---:|---:|---:|
| beta.1 第一次解释 | 159,146 | 148,992 | 93.6% |
| beta.1 第二次解释 | 187,980 | 178,048 | 94.7% |
| beta.2 新回复自动解释 | 156,592 | 146,432 | 93.5% |

token 是模型计算文本用量的单位。命中率按服务器返回的**本次命中缓存的输入 token ÷ 本次全部输入 token**计算。上述解释均沿用主聊天的 `gpt-6.1-sol` 模型和 high 思考强度。

这些数字来自本地样本。实际命中率随输入内容、模型和缓存保留情况变化；每次解释仍需要生成新的内容，并计入账号或服务的用量。详细计数和测试条件见 [VALIDATION.md](VALIDATION.md)，缓存机制见[官方说明](https://developers.openai.com/api/docs/guides/prompt-caching)。

## 生成速度实测

2026-10-18，使用 0.5.0-beta.1 解释同一聊天的两条完整回复，并与这两条回复对应的官方自动填充结果记录对照：

| 对应回复 | 官方自动填充 | 本插件生成完整解释 |
|---|---:|---:|
| 回复 A：首次解释 | 14.8 秒 | 26.5 秒 |
| 回复 B：后续解释，后台自动复用 | 18.5 秒 | 18.2 秒 |

官方用时从主回复结束计至预测结果写入日志；插件用时从提交解释请求计至完整结果更新，后台的首次启动在提交前已完成。两边请求发生于不同时间，均未测量屏幕实际刷新时刻。官方生成下一条输入建议，插件在这两次测试中分别生成 132、144 字的解释，文字返回后逐步显示。详细计时见 [VALIDATION.md](VALIDATION.md)。

2026-10-22，包含本次修复的版本在一条新回复结束后约 1.1 秒自动开始解释，从主回复结束到完整解释数据更新共 24.4 秒，缓存命中 93.5%。这次没有匹配的官方自动填充计时，以上表作为历史对照。

**插件已自动管理后台的启动、复用和关闭，无需额外开启或配置。** 实际耗时随上下文长度、沿用的模型与思考强度、服务端响应和网络情况变化。

## 安装条件

1. Windows 10/11 x64，已安装 Codex 桌面端并登录。
2. Node.js **22.13 或更新版本**，`node.exe` 能从终端找到。
3. Codex 的 `codex.exe` 能从终端找到；找不到时用安装参数指定其完整路径。使用支持 `plugin marketplace`和 `thread/fork` 的版本。
4. Git 已加入 PATH，且能连接 GitHub。
5. 已有微软 WebView2 Runtime。安装包包含 WebView2 SDK 所需组件，不包含浏览器运行环境。

## 安装：交给你自己的 Codex

**首次安装直接使用最新版。beta.1 / beta.2 用户运行一次新版安装脚本后，即可启用自动更新，无需先卸载。** 在 [Releases](https://github.com/Jupiterofyear/codex-reply-explainer/releases) 下载文件名以 `-plugin-windows-x64.zip` 结尾的插件包。

把项目链接和下面这段话发给自己的 Codex：

> 请帮我安装或更新 Codex Reply Explainer（Codex 回复解释），并启用自动更新。先阅读 README、PRIVACY.md 和 install.ps1，检查 Windows、Node.js、Git、Codex 和 WebView2 是否满足要求。下载最新版 Windows x64 插件 ZIP，解压到我选择的长期保留目录，运行安装脚本。已有安装时沿用原来的 Codex 存储目录和解释数据目录，保留窗口大小与位置。此版不需要 hook 授权。重启 Codex，核对插件版本、打开入口和点击按钮后的解释生成。不要修改桌面端源码。

安装脚本将本项目 GitHub 主分支登记为插件来源。Codex 负责下载和更新运行文件，安装时会获取该分支当前的构建版本，包含本页介绍的解释和提问功能。个人安装设置单独保存，窗口位置留在原解释数据目录中。

### 自己执行安装

1. 关闭解释小窗，将最新版 Windows x64 插件 ZIP 解压到长期保留的文件夹。
2. 在该文件夹打开 PowerShell：

   `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1`

   首次安装时，可以指定解释数据保存位置：

   `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -DataDirectory "D:\ReplyExplainerData"`

   已安装公开版时，省略 `-DataDirectory` 会沿用原数据目录。`-CodexHome` 可指定原安装使用的 Codex 存储目录；若 Codex 不在 PATH，用 `-CodexPath` 指定其 exe 完整路径。Node.js 和 Git 必须在 PATH 中。
3. 重新打开 Codex 桌面端，使插件可用；当前版本不注册 hook，无需授权。
4. 打开解释小窗，确认窗口设置和点击按钮后的解释生成正常。

安装会写入：

| 位置 | 用途 |
|---|---|
| Codex 存储目录中的配置、插件来源和缓存 | 官方插件登记、自动更新下载及运行副本 |
| Codex 存储目录的 `plugins/reply-explainer-settings.json` | 本机的解释数据目录和 Codex 程序位置；更新插件时保留 |
| 所选解释数据目录 | 解释临时数据、诊断日志和窗口位置 |
| 解压文件夹的 `.local` | 快捷启动信息、安装回执和安装临时文件 |

首次安装默认使用解压文件夹的 `.local/data` 保存解释数据。已有安装会沿用原目录；如果它位于旧解压文件夹内，请保留该目录。安装脚本不修改桌面端源码。

## 打开和使用

日常入口在 Codex 内，无需桌面快捷方式，也不会随 Codex 自动弹出。点击聊天右侧的“＋”打开新标签页，在工具中选择“Codex 回复解释（悬浮窗）”；已最小化时再次点击同一入口会还原现有窗口，保留其内容，不另开一份。

1. 打开要解释的本地聊天，点击**聊天区域右上角的“＋” → 工具中的“Codex 回复解释（悬浮窗）”**，打开小窗。
2. 小窗会选中这段聊天，等待你点击底部的“解释当前对话”，再解释最近一条完整回复。附带打开的内部面板可以关闭，保留悬浮小窗即可。如果保留内部面板，之后可点击其中的“打开悬浮窗”直接重开。
3. 切到“提问”页，可以直接结合这段聊天追问。Enter 发送，Shift+Enter 换行；生成时右下角发送箭头变为停止方块，点击后保留已生成内容，还能继续追问。思考提示位于对应输出段落前，逐秒显示用时。
4. **切换主聊天时自动选择对应标签。** 保持主窗口侧栏显示选中的聊天，只保留一个 Codex 主窗口。点回旧标签可查看它的解释和问答，并针对该标签继续操作；主窗口再次切换聊天时才自动跟随。自动识别不操作剪贴板。
5. 发消息和切换聊天不会生成解释。需要解释最新完整回复时，点击解释页底部按钮。
6. 可以拖动窗口、调整宽高。**关闭时保存大小和屏幕位置，下次打开自动恢复**；关闭小窗同时停止解释和提问后台，并清理所有标签中的临时内容。后台意外退出时会保留已生成文字并显示错误；点击“解释当前对话”可重新启动后台并生成解释。

另一个打开方式：安装完成后，双击解压目录的 `open.cmd`，再点解释页底部的“解释当前对话”。它会定位已安装的当前版本，并使用原来的数据目录。

更新前已打开的聊天可能保留旧的失败连接。若更新后仍提示“未能显示”，等运行中的任务结束，完整退出并重新打开 Codex，再从同一入口打开；仅点击面板里的“重试”可能继续使用旧连接。

如果聊天名称没有更新，检查主窗口侧栏是否显示选中的聊天，以及是否有同名聊天；具体原因会显示在小窗中。解释只在点击底部按钮后生成。普通 Chat 不提供此版本需要的本地记录；它不会被转换成新的主聊天。

## 自动更新与卸载

从 **0.5.0-beta.3** 开始，安装脚本默认启用官方 Git 插件来源更新。

- **新用户**：安装一次即可。
- **beta.1 / beta.2 用户**：关闭小窗，运行一次新版安装脚本，重启 Codex。脚本会沿用已有解释数据目录和窗口设置。
- **之后**：Codex 后台启动时检查 GitHub 主分支，发现已更新的插件文件后下载并刷新安装副本。可以通过重新打开 Codex 触发检查；需要能连接 GitHub。已打开的小窗关闭后重新打开，以加载新版。
- 当前版本通过只读识别侧栏来同步，不再注册生命周期 hook。

自动更新跟随的是主分支中的 `.agents/plugins/marketplace.json` 和 `plugin/`。**只上传 Release 附件不会触发自动更新。** 发布者必须把经过构建、测试的安装文件一起提交到主分支。发布步骤见 [CONTRIBUTING.md](CONTRIBUTING.md)。

更新保留原数据目录、窗口大小和位置。插件不安装额外的常驻更新程序。Codex 自身负责检查和下载；这不保证发布后立即到达每个用户，也不强制关闭正在使用的窗口。

### 卸载

```powershell
codex plugin remove reply-explainer@reply-explainer-preview
codex plugin marketplace remove reply-explainer-preview
```

随后可删除解压目录、自己指定的解释数据目录，以及 Codex 存储目录中的 `plugins/reply-explainer-settings.json`。自定义 `CODEX_HOME` 的安装应在相同环境中卸载。

构建需要 Windows x64 的 .NET Framework C# 编译器。WebView2 SDK 的必要文件和许可证位于 `vendor/webview2`。构建还会生成供自动更新使用的 plugin 目录和 .agents/plugins/marketplace.json；其余输出位于项目内的 `dist`、`.local`，安装包输出到 `.local/releases`。

## 当前限制

此版本依赖本地记录格式、数据库结构和 Codex 的分支接口，桌面端更新后可能需要适配。它保留已有有效历史，但独立解释后台不等于桌面端原后台的全部运行状态；缓存是否命中以服务器返回的计数为准。

本测试版通过源码和手动安装包分发。当前版本不再包含生命周期 hook。参阅[官方插件文档](https://developers.openai.com/plugins/build/plugins)。
